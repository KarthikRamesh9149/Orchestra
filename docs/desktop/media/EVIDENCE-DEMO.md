# Evidence walkthrough provenance

Captured on 16 September 2026 in the internal Mac desktop app. The fictional
Northstar PRD is generated by `scripts/desktop/make-demo-documents.mjs` and was
uploaded through the native file picker and Memory UI, not inserted into a mock
screen. No customer content appears in the captures.

The demonstrated journey is:

1. Select Docs and ask whether PDF export is in the PRD's launch scope.
2. Observe the explicitly labelled evidence-only response (no AI key in this profile).
3. Follow its document citation into the actual uploaded source.
4. View the document's paged extracted text.

The 24-second H.264 video and four-state looping GIF are an **edited walkthrough
of real app captures**, not continuous screen recording or a speed benchmark.
They do not demonstrate real AI synthesis, connected external providers or a
successful approval. The visible PARTIAL state is retained honestly.

Rebuild with macOS system frameworks, without a paid renderer:

```sh
swift scripts/desktop/render-evidence-demo.swift .desktop/demo-content .desktop/evidence-demo-new
```

The script refuses to overwrite outputs. The source captures remain local under
the ignored `.desktop` directory. Screenshots used in the published repository
assets are synthetic and were inspected visually. No external music, stock
footage or font binaries are included. The official GitHub CLI attachment flow
is used to obtain a native video player in GitHub Markdown; a relative MP4 link
alone is not an inline player.

Attachment is retained in private repository issue #1. An unauthenticated request
to the attachment URL returned 404 after upload; the authenticated GitHub player
reported 24 seconds, 1440×1120 and started playback successfully. This establishes
access protection at the time of inspection, not a guarantee about future sharing
settings. The isolated official GitHub CLI 2.101.0 archive was checked against its
release SHA-256 list; the user's installed CLI was not replaced.
