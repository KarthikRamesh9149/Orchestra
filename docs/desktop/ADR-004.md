# ADR 004: local UI contracts and restart continuity

Status: implemented candidate; Step 4 acceptance is not yet complete.

## Context

The packaged React application must use the existing authorized product services without hosted signup. The renderer must not receive installation credentials or a generic network/filesystem proxy. Existing browser continuity uses session storage and does not survive desktop process termination.

## Options

1. Reimplement each product page with separate IPC DTOs: duplicates business contracts and risks drift.
2. Expose a general fetch bridge or loopback credential: rejected; grants unnecessary authority to renderer code.
3. Serve an explicit, method-bound local API inventory through the trusted custom origin, with credentials held in main: selected.

## Decision

The main process forwards only reviewed routes to its owned loopback engine. Caller credentials/cookies are discarded. The native bearer is short-lived and refreshed over private child IPC. Backend membership, input validation and approval checks still apply. Unknown routes, shared administration and external provider writes fail closed. Request bodies are bounded; response status and streaming are preserved.

The route inventory is generated from a selected domain list and checked into source. Its diff requires review. Adding an upstream route does not automatically authorize it at runtime until the inventory is regenerated and reviewed.

Local onboarding records privacy acknowledgement and selected workspace with atomic private-file writes. The local principal is not a verified email identity. Account passwords and invitations are unavailable locally, with an explanation. External AI and provider/agent qualification remain Step 5; shared servers remain Step 6.

For the current local-only desktop, bounded drafts and render-cache continuity use the app profile's local storage. No credentials are included. Hosted browser sessions retain session storage. Authoritative transcripts remain in PostgreSQL. Identity changes clear cached content. Document and cache confidentiality rely on macOS account permissions and disk encryption, as disclosed during onboarding.

## Trade-offs and consequences

- Reuses existing React and backend DTOs, including real SSE and upload reconciliation.
- Requires explicit checks for route coverage and capability presentation; the first packaged tests caught excluded subscription reads and an unqualified connector action.
- Main remains privileged; renderer compromise can exercise the current owner's allowlisted product actions, but cannot obtain credentials or choose arbitrary network destinations.
- Step 6 must replace the local-only continuity decision with separate local/remote storage and the agreed disabled-by-default shared offline cache. Do not enable remote mode using the current desktop flag alone.
- Offline partial indexing is shown explicitly, not as endless processing or full semantic readiness.
