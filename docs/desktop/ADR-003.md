# ADR-003: Restricted native shell and owned runtime guardian

Status: Implemented Mac candidate; cross-platform completion blocked.
Date: 2026-09-10
Decider: Karthik Ramesh through the approved Step 3 scope.

## Context

Consumer local mode cannot rely on PATH, Docker, Supabase or Railway. The renderer must not hold runtime credentials or expose a generic filesystem/network/shell bridge. Step 4 owns onboarding and the existing React application's complete desktop adapter. Production orchestrav2 remains outside scope.

## Decision

Electron main loads only packaged `orchestra://app` assets, denies permissions and foreign navigation, validates IPC sender/frame and uses strict named command schemas. Sandbox and context isolation are enabled; Node integration is disabled. Credentials are encrypted through Electron safeStorage with no plaintext fallback. Main sends installation authority over private child IPC, not renderer state or command arguments.

A bundled Node child owns the local PostgreSQL process and engine. It binds an ephemeral loopback port, migrates the owned database, grants a separate non-owner runtime role and starts the original portable engine/worker. Each HTTP request still needs installation authority and the existing actor/project authorization. Named bridge operations use an installation-local principal, not a fabricated verified hosted account. Parent disconnection shuts down the guardian and its database; interrupted initialization is preserved, not deleted.

Mac binaries are built from checksum-pinned PostgreSQL 17.11, OpenSSL 3.5.8 and pgvector 0.8.6 sources. Node 24.19.0 is checksum-pinned. Mach-O dependencies are relocated into the bundle; only local ad-hoc signatures are applied. Native hashes detect accidental corruption but are **not** a substitute for Step 7 publisher signing/tamper protection.

## Options considered

| Option | Complexity / cost | Benefits | Consequences |
| --- | --- | --- | --- |
| Bundled Node guardian | Medium, no infrastructure purchase | Reuses backend/Prisma runtime; IPC parent-loss cleanup | Separate binary inventory and lifecycle tests |
| Electron utility process | Medium, no purchase | Fewer distributed runtimes | Different IPC/bootstrap contract; more Electron-specific backend coupling |
| Renderer HTTP/FS proxy | Low initial effort | Fast generic integration | Excessive renderer authority; rejected |
| User-installed PostgreSQL/Docker | Low packaging effort | Existing local tools | Violates consumer installation requirement; rejected |

## Trade-offs and consequences

- Keeping the bridge narrow requires explicit Step 4 feature adapters. The current packaged React application truthfully renders its disconnected state rather than pretending its old hosted API is available.
- Full backend dependencies and migration CLI are retained in this internal candidate for reproducibility. Size reduction and complete bundled dependency/legal review remain necessary before public distribution.
- The native guardian handles ordinary termination/parent IPC loss. Hard-killing the guardian itself, platform-specific process trees, sleep/wake and interrupted migrations require further qualification; no unsafe PID-based cleanup is used.
- Mac source compilation used this host's SDK. Compatibility with older supported macOS versions is not certified.
- Windows x64 native binaries, protected initialization and actual Windows installation tests remain unresolved. The build fails closed rather than creating a misleading Windows artifact.
