# ADR-001: App-managed local engine and authoritative shared server

Status: Accepted architecture; implementation pending Steps 2–7.
Date: 2026-09-10
Deciders: Karthik Ramesh, through the approved eight-step plan.

## Context

Reuse the existing React/TypeScript product without carrying hosted signup, production services, or Redis into the consumer local-mode requirement. Preserve evidence → interpretation → proposal → authorized review → accepted truth. Keep current UI styling and product capabilities. No paid services, purchases or GitHub Actions are authorized.

## Decision

Electron hosts trusted packaged UI. A main-process supervisor owns pinned PostgreSQL/pgvector, backend, parsers and a durable database-backed local worker. Explicit runtime profiles are desktop-local, self-hosted and managed. Keep the server worker implementation. No consumer Docker or PATH-installed developer tooling requirement.

Local workspaces use an installation-local owner and isolated application data. Shared workspaces use one authoritative selected server. Identities, credentials and caches are isolated by mode/server/workspace. No silent local-to-shared publishing or peer synchronization.

Renderer has no Node integration, filesystem authority or secrets. A narrow typed bridge exposes workspace selection, native pickers, status and cancellable operations. Local endpoints require authentication. Credentials use OS-protected storage; database/document protection relies on OS disk encryption plus separately encrypted backups. Do not claim encrypted database-at-rest merely because credentials are protected.

## Options considered

| Option | Complexity | Operational consequence |
| --- | --- | --- |
| Electron + bundled PostgreSQL | Higher packaging and update work | Best reuse of current services, SQL semantics and pgvector |
| Browser wrapper around managed API | Lower packaging work | Does not meet independent local-workspace requirement |
| Rewrite backend around SQLite | High service and migration rewrite | Smaller runtime but increased semantic and parity risk |
| Require consumer Docker | Lower bundling work | Fails install-without-developer-tools requirement |

## Consequences

Mac Apple Silicon and Windows x64 each need bundled-runtime, clean-machine, upgrade and recovery qualification. External AI latency and cost are disclosed separately; offline reading and lexical search must work, fully offline generation is not in this release. Signing and provider approvals are real blockers, not flags to bypass.
