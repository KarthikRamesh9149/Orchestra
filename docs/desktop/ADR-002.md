# ADR-002: Durable engine foundations before runtime activation

Status: Foundation implemented; runtime activation and Step 2 gate pending.
Date: 2026-09-10
Decider: approved desktop plan; no production changes authorized.

## Context

The imported application selects inline or BullMQ jobs, uses Redis for some AI limits, and returns mock providers when no external key exists. Merely renaming an environment would not create a safe local engine.

## Decision

Implement a PostgreSQL queue with unique payload-bound idempotency, atomic SKIP LOCKED claims, random owner tokens, monotonic fencing, heartbeat, expiry, bounded explicit retries and cancellation of queue ownership. Preserve legacy handler execution until its effects and cancellation semantics are verified.

Expired claims become explicitly failed with `worker_lease_expired`. Do not automatically replay an unfenced legacy handler or imply that fencing acknowledgement makes its effects exactly-once. An authorized retry must verify handler effect idempotency. A real process-kill test verifies this initial recovery contract.

Runtime profiles are an independent validated contract, not a staging flag. They must be consumed by the composition adapter before users can select local mode. Local profile requires loopback PostgreSQL/API, absolute private storage and PostgreSQL jobs with no Redis. Server profiles preserve the existing queue implementation.

Private file storage provides atomic publication, bounds, path/symlink checks, private POSIX modes and no direct filesystem URLs. It does not replace API authorization or protect against a fully compromised OS account. Windows ACL and packaged runtime qualification remain Step 3/7 requirements. Secrets are atomically published in a separate caller-selected credentials directory; OS vault integration remains Step 3.

Backup encryption is a bounded authenticated AES-GCM envelope with a passphrase-derived key, not yet a database/filesystem backup orchestrator. It does not claim database encryption at rest. Use OS disk encryption for live data files.

## Alternatives and consequences

- Inline queue: simplest, but loses durable work and blocks requests; rejected for local engine.
- Automatic lease replay now: convenient, but unsafe before verifying every handler's effects; deferred.
- Explicit failure/retry: honest recovery and no permanent spinner at the queue level; domain-level research/document state reconciliation is still required before activation.
- Rewriting original migrations: loses provenance; rejected. Plain PostgreSQL bootstrap instead creates non-login compatibility roles and extension search path before applying preserved history.

## Required remaining work

1. Wire composition and worker lifecycle; persist AI budgets and remove remaining local Redis dependence.
2. Reconcile queue/domain state and verify idempotent handler effects, cancellation and retry.
3. Map SQL tables in Prisma and document least-privilege runtime provisioning separately from the migration superuser.
4. Replace absent-key mock providers with honest offline behavior; verify lexical read/search and cited evidence-only answers.
5. Integrate authenticated private storage and full encrypted database/files backup/restore.
6. Run upload → parse → index → citation → authorized approval → restart with the real local application.
